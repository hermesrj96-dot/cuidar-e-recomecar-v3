- Banco D1 existente: cuidar-recomecar-v3
- Tabelas já criadas anteriormente no Console D1:
  categories, products, customers, orders, order_items, settings, audit_logs

ANTES DE PUBLICAR — BACKUP E IDENTIFICADOR D1
---------------------------------------------
1. Faça backup do D1 na tela do banco, se a opção estiver disponível.
2. Abra Cloudflare Dashboard > D1 > cuidar-recomecar-v3.
3. Copie o Database ID (não é senha nem token).
4. Abra wrangler.toml e substitua o texto:
   PREENCHER_COM_O_DATABASE_ID_DO_D1_EXISTENTE
   pelo Database ID copiado.
5. Não altere o nome do banco nem a variável DB.

IMPORTAR O CATÁLOGO (OPCIONAL)
------------------------------
As sete tabelas já existem. NÃO execute nenhum SQL CREATE TABLE.
Para inserir os 20 produtos de referência, use o arquivo:
  sql/IMPORTAR_CATALOGO_V2_SEGURO.sql

Com Wrangler instalado e autenticado, na pasta do projeto execute:
  npx wrangler d1 execute cuidar-recomecar-v3 --remote --file=sql/IMPORTAR_CATALOGO_V2_SEGURO.sql

O script usa INSERT ... WHERE NOT EXISTS para não inserir novamente produtos com o mesmo nome. Se preferir começar com catálogo vazio, pule esta etapa e cadastre os produtos pelo painel.

INSTALAÇÃO NO COMPUTADOR (RECOMENDADA)
--------------------------------------
Requisitos: Node.js LTS e conexão com internet.

1. Extraia o ZIP.
2. Abra o terminal dentro da pasta CUIDAR_RECOMECAR_V3_UPLOAD.
3. Instale/execute Wrangler:
   npm install
   (Se não houver package.json, use diretamente: npx wrangler --version)
4. Autentique na Cloudflare:
   npx wrangler login
5. Confira a configuração e o Database ID em wrangler.toml.
6. Configure a senha do painel como segredo (não coloque senha no código):
   npx wrangler secret put ADMIN_PASSWORD
   Digite uma senha forte quando solicitado.
7. Configure a chave de assinatura das sessões:
   npx wrangler secret put SESSION_SECRET
   Informe uma sequência aleatória longa, com pelo menos 32 caracteres.
8. Publique Worker + arquivos da loja:
   npx wrangler deploy
9. Teste:
   https://SEU-WORKER.workers.dev/api/health
10. Abra a loja:
   https://SEU-WORKER.workers.dev/
11. Abra o painel:
   https://SEU-WORKER.workers.dev/admin.html

SE O WORKER JÁ TEM A ASSOCIAÇÃO D1 NA DASHBOARD
------------------------------------------------
O arquivo wrangler.toml também declara a associação DB. Ao publicar via Wrangler, confirme que o Database ID é o mesmo banco existente. Não crie outro banco e não mude o binding DB.

LIMITES E SEGURANÇA
-------------------
- Nenhuma senha ou token está incluído no ZIP.
- Não envie ADMIN_PASSWORD, SESSION_SECRET, token ou chave API por WhatsApp ou aqui no chat.
- O sistema não processa pagamentos com cartão. Não colete número do cartão, CVV ou senha.
- O botão público atual direciona a conversa para WhatsApp; o endpoint de pedidos fica disponível para futura integração com formulário de checkout.
- Imagens de produtos usam URLs externas; R2 não é necessário nesta etapa.
- Antes de usar com clientes reais, adicione proteção anti-spam (ex.: Turnstile), aviso de privacidade/consentimento LGPD, teste de backup e revisão de segurança.
- Os preços do catálogo são referências importadas do arquivo anterior e devem ser conferidos/atualizados antes de anunciar.

UPLOAD DIRETO PELO EDITOR WEB
-----------------------------
O editor rápido do Worker não importa um ZIP com múltiplos arquivos e pastas. Para publicar o conjunto completo (Worker + pasta public + configuração D1), use Wrangler no computador ou conecte um repositório Git. Não cole o conteúdo de vários arquivos dentro de worker.js.
